# Queued Follow-ups and Steering

You do not have to wait for a running session to finish before you write the next message.

## Queue a follow-up

While a session is running, type in the composer and send as usual. The message does not interrupt the run; it appears as a **Queued** card above the composer.

- When the run ends, the queued message is sent automatically as the next turn.
- Only one message is queued per session. Sending another one replaces it, and the replaced text is put back into the composer so nothing is lost.
- Remove the queued message with the `x` on its card.
- If the run fails, the queued message stays in place and is not sent, so you can decide what to do.

## Steer a running session

To change direction right away instead of after the run, queue your correction and then press **Stop**.

With a message queued, **Stop** ends the current run without marking it as cancelled, and the queued message is sent immediately. The agent continues with your new instruction and keeps the conversation so far.

Without a queued message, **Stop** cancels the run as usual.
